Projects and learning experiences

These descriptions focus on coursework and practical lab learning. They explain the technologies explored, the challenges encountered, and the professional lessons I am taking forward.

Project 01 · Cybersecurity · Security monitoring

Wazuh SIEM / HIDS – Security Monitoring Lab

Project context. This learning project introduced me to centralized security monitoring using Wazuh. The lab involved connecting Ubuntu and Windows systems to a monitoring environment and examining security information such as file-integrity changes, authentication activity, and alerts.

Challenges and approach. A key challenge was getting the monitored systems and the Wazuh platform to communicate correctly. The setup required attention to agent configuration, connectivity, firewall settings, certificates, and enrollment keys. I worked through issues by checking configurations step by step, reviewing connectivity, and learning how the server and agents exchange information. I also had to move beyond simply noticing an alert and think about what the event might mean and what would need further investigation.

Technical learning. The lab strengthened my understanding of SIEM/HIDS concepts, endpoint agents, file-integrity monitoring, authentication-event monitoring, and reviewing security alerts.

Professional and personal lesson. Security work calls for patience, sound judgment, and respect for the information entrusted to us. Protecting systems also means protecting people. I want to approach security responsibilities with integrity, investigate carefully, and avoid making claims before I have evidence.
Project 02 · Database management · SQL data analysis

JFK Flight Delays and Chinook Media Store – PostgreSQL Data Analysis

Project context. This project brought together two database learning exercises using PostgreSQL and DataGrip: exploring the JFK Flight Delays dataset and working with the Chinook Media Store database. The tasks helped me practise retrieving, combining, and analysing structured information to answer questions using data rather than assumptions.

Challenges and approach. Some of the challenges involved understanding how tables were related, choosing the right joins, and handling details that could affect the accuracy of the results, including missing values, differences in schema, and date or time-zone information. More advanced queries also required careful planning. I used SQL joins, Common Table Expressions (CTEs), and window functions, then checked the query logic and results to make sure they answered the intended question.

Technical learning. These exercises strengthened my practical experience with PostgreSQL, SQL, and DataGrip. I gained experience combining data from related tables, using CTEs and window functions, accounting for null values and time-related data, and validating query results. The work also helped me see how database analysis can turn raw records into information that supports better decisions.

Professional and personal lesson. This project reminded me that accuracy and honesty matter whenever people rely on information to make decisions. It is tempting to accept the first result a query produces, but responsible work means checking assumptions, understanding limitations, and being transparent about what the data does and does not show. I want to bring that same care and integrity to every system and dataset I am trusted to work with.
Project 03 · Secure infrastructure · Linux and cloud concepts

Heritage Vault 2.0 – Linux and High-Availability Infrastructure

Project context. Heritage Vault 2.0 / PromisedLand.com was an infrastructure learning project exploring how server, storage, traffic-management, and security components work together. Technologies covered included AWS EC2, Ubuntu Linux, Logical Volume Management (LVM), ZFS, HAProxy, Keepalived, and SELinux.

Challenges and approach. The main challenge was understanding how separate infrastructure components affect one another. Storage configuration, service availability, traffic distribution, permissions, and security settings cannot be treated as unrelated tasks. I worked through the requirements in stages, reviewed configurations, and used troubleshooting to understand how a change in one area could affect the overall environment.

Technical learning. The project strengthened my understanding of Linux server administration, cloud compute concepts, storage management, load balancing, high availability, and security controls such as SELinux and permissions.

Professional and personal lesson. Reliable infrastructure depends on preparation, patience, and accountability. I want to become the kind of administrator who checks the details, considers the wider impact, and takes responsibility for keeping systems dependable for the people who use them.
